# 02. 화면과 사용자 경험

## 작품 상세의 공동 S 추천 · 2026-10-10 (작성·실행 미검증)

`/works/[slug]` 리뷰 아래에 ‘이 작품의 S 독자들이 함께 좋아한 작품’ 최대 6카드를 배치한다. 기존 WorkCard/허가 표지·텍스트 커버를 재사용하고 각 카드에 ‘공동 평가 n명 중 s명이 이 작품도 S’를 표시한다. 응답의 계산 시각은 한국 시간으로 표시하고 접힌 설명에 표본·정렬 기준을 안내한다. 표본 부족은 실제 빈 결과일 때만, API 미설치/조회 실패/접근 불가는 별도 안내로 표시한다. Suspense로 추천 로딩을 분리해 추천 실패가 작품/리뷰 표시를 막지 않도록 작성했다. 기존 같은 장르 최근 등록순 목록은 유지하며 공동 S 근거로 바꿔 부르지 않는다.

## 취향 비교 화면 · 2026-10-09 (작성·실행 미검증)

타인 프로필의 ‘나와 취향 비교하기’에서 `/compare/[username]`으로 이동한다. 비회원은 로그인 후 해당 조건으로 복귀하고 자기 프로필 비교는 안내한다. 점수·공통 편수·티어/별점 기준 편수·표본 안내, 공통 평가/함께 S/평가가 갈리는 작품 탭, 20편 페이지를 제공한다. 탭 변경은 첫 페이지로 돌아가고 잘못된 조건은 입력 안내, 없는/차단/비활성 프로필은 같은 404를 사용한다. 5편 미만은 점수나 meter를 만들지 않으며 실제 0점과 구분한다. 내 비공개 평가 포함·나만 보는 결과임을 안내하고 알고리즘 설명을 접어서 제공한다. 새 RPC 미설치는 준비 안내다. 현재 공개·평가 변경에 따라 페이지가 바뀔 수 있으며 snapshot을 보장하지 않는다.

## 커뮤니티 작품 연결 병합 · 2026-10-08 (작성·실행 미검증)

`/admin/works/merge` 미리보기에 작품 연결을 옮길 게시본/초안 수와 중복 정리 건수를 표시한다. 글 원문/초안/작성자별 연결은 관리자 화면에 표시하지 않는다. 미설치 DB 응답에 community 집계가 없으면 준비 안내를 보여주고 0건으로 만들지 않는다. 합쳐질 작품과 남길 작품이 함께 있으면 각 게시본·초안에서 먼저 나온 위치를 유지한다. 원본 작품이 공개 불가라면 연결을 옮겨 글을 재노출하지 않고 충돌로 막는다. 남길 작품의 현재 공개 상태와 기존 개인 기록 충돌 안내는 유지한다.

내 글 편집에서 `/me/posts/[id]/merge-history`로 이동해 병합된 작품 이름과 게시본/초안 연결의 전후 개수·변경 시각을 20건씩 본다. 본인 글만 열람하며 삭제한 글은 접근하지 못한다. 새 이력 API 미설치는 빈 이력과 구분한 준비 안내다. 본문과 공개 상태는 바꾸지 않고 초안을 자동 게시하지 않는다. 변경된 게시본/초안 버전은 새로 불러오게 해 병합 전 편집 내용으로 연결을 덮어쓰지 않도록 한다.

## 리뷰 토론 화면 · 2026-10-08 (작성·실행 미검증)

`/reviews/[id]`에 실제 좋아요 수/목표 상태 버튼과 최신 댓글 20개를 연결한다. `/reviews/[id]/comments`에서 전체 댓글 및 원 댓글별 작성순 답글을, `/reviews/[id]/comments/[commentId]`에서 알림이 가리키는 정확한 댓글을 읽는다. 답글은 한 단계다. 리뷰·원 댓글·본인 댓글의 스포일러 표시를 합쳐 본문을 가리고 명시적으로 펼칠 때 현재 버전을 다시 확인한다. 본인 수정/삭제, 타인 신고/차단을 제공하며 삭제된 원 댓글은 본문/작성자 없이 기존 답글 문맥만 남긴다.

작품별·회원별 리뷰 목록은 `sort=latest|likes|popular`와 page를 유지한다. API 미설치 시 최초 게시일 최신순으로 표시한다는 안내를 보여주고 실제 집계가 없으면 좋아요 수를 표시하지 않는다. 상세의 기존 리뷰 본문은 유지하며 새 토론만 준비 안내로 바꾼다. 준비 안내를 console.error로 출력하지 않는다. 그 외 예상하지 못한 오류는 정상 빈 목록으로 위장하지 않는다.

내 댓글 신고 결과는 `/me/review-comment-reports`, 운영 큐/검토는 `/admin/review-comment-reports`·`/admin/review-comments/[id]`다. 기존 리뷰 신고 화면에서 이동하며 현재 역할 확인 뒤만 조회한다. 검토 원문은 별도로 펼친다. 리뷰 좋아요/댓글/답글 알림은 원문 없이 정확한 리뷰/댓글로 이동한다. 실제 브라우저 흐름은 미검수다.

## 현재 인증 흐름 · 2026-10-07 (코드 작성·실행 미검증)

`/auth/sign-up`은 아이디·비밀번호·확인·필수 동의를 받으며 이메일 인증 없이 가입 → 자동 로그인 → 안전한 원래 목적지(기본 `/me/library`)로 이동한다. 프로필/비공개 기본 설정은 가입 때 생성하고 추가 온보딩을 요구하지 않는다. 자동 로그인 실패 시 가입된 계정을 지우지 않고 로그인 화면으로 안내한다. `/auth/sign-in`은 같은 아이디를 사용한다. `/settings/account`는 내부 Auth 식별자를 연락 이메일로 표시하지 않으며 현재 비밀번호를 입력해 변경한다. 아이디 계정의 연락 이메일·복구 메일은 아직 제공하지 않는다. 기존 Stitch 배치와 OAuth의 별도 온보딩은 유지한다. MCP 연결과 `zwzncrdlqnthxgdvsqxq` DB 설치는 완료했고 실제 가입·로그인·브라우저 흐름은 사용자 검수 요청 대기다.

## 1. 디자인 방향

### 커뮤니티 연결 대기 안내 · 2026-10-08 (코드 수정, 실행 미검증)

`/community` 조회에서 DB 함수/테이블이 없거나 API schema cache가 이를 인식하지 못하는 응답은 커뮤니티 준비 안내로 처리한다. 정상 조회의 빈 목록과 구분하며 글쓰기/내 글 진입 링크를 숨긴다. 다시 불러오기는 현재 검색어·주제·작품·정렬·페이지를 보존한 GET 요청이다. 실제 조회가 성공하면 목록과 글쓰기 진입이 다시 나타난다. 제품 화면에는 DB 오류 원문/테이블명/SQL을 표시하지 않고 예상하지 못한 오류는 기존 오류 경계로 전달한다. 원격 DB 복구나 실제 화면 동작은 아직 확인하지 않았다.

### 공통 본문 높이·푸터 배치 · 2026-10-08 (코드 수정, 화면 검수 미실행)

이용약관·개인정보처리방침처럼 내용이 짧은 페이지에서도 공통 본문이 화면의 남는 높이를 채우도록 작성했다. body를 최소 100dvh(미지원 시 100vh)의 세로 flex로 두고 헤더/푸터의 실제 높이를 제외한 공간을 main에 배분한다. 내용이 길면 문서 높이가 자연스럽게 늘고 푸터는 본문 뒤에 이어진다. main에서 자식 여백을 포함하도록 flow-root를 사용하며 준비/404/오류/로딩 화면의 별도 65vh 최소 높이는 제거했다. 모바일은 기존 하단 메뉴 여백에 기기 safe area를 반영하고 768px 이상에서는 기존처럼 하단 메뉴 여백을 없앤다. 약관/개인정보 안내의 문구는 이번 수정 대상이 아니다. 실제 브라우저·화면 크기 변경·모바일/키보드 검수와 자동 검사는 사용자 요청 전까지 미실행이다.

### 커뮤니티 토론 증분 · 2026-10-08 (코드 작성, DB 미적용·실행 미검증)

글 상세에서 좋아요/취소와 댓글을 제공한다. 좋아요는 DB 응답 후 갱신하며 저장 응답이 불명확하면 현재 상태 다시 불러오기를 안내한다. 본인 글에는 좋아요할 수 없다. 댓글은 공개 게시 확인과 기본 스포일러 선택을 받고, 실패 시 입력과 재전송 ID를 유지한다. 본인 수정·삭제, 타인 신고·작성자 차단을 연결했다. 글/원 댓글/개별 댓글 중 하나라도 스포일러면 최초 응답에 본문을 싣지 않고 별도 펼치기로 현재 버전과 공개 범위를 재확인한다.

`/posts/[id]/comments`에서 원 댓글은 최신순, `?parent=[commentId]`의 답글은 오래된 순으로 20개씩 조회한다. 답글은 한 단계까지만 허용하며 삭제된 원 댓글은 이름/본문 없는 안내와 기존 답글만 남기고 새 답글은 막는다. `/posts/[id]/comments/[commentId]`는 알림에서 정확한 댓글로 이동하는 경로다. `/me/post-comment-reports`는 본인 신고 결과, `/admin/post-comment-reports`·`/admin/post-comments/[id]`는 운영 큐/명시적 원문 확인·숨김/복구/기각이다. 글 신고 화면과 운영 메뉴에도 연결했다.

`/community`의 최신순/최근 7일 인기순은 기존 주제·검색어·작품 조건과 페이지 링크에 함께 유지한다. 카드에 유효 좋아요 수, 인기순에서는 최근 좋아요·서로 다른 댓글 참여자 수와 점수를 표시한다. 같은 사람이 여러 댓글을 써도 한 명이며 본인/삭제/숨김/차단/비활성 활동은 제외한다. 목록은 매 요청의 현재 상태로 계산하므로 페이지 이동 중 순서가 달라질 수 있다. 글 좋아요·댓글·답글 알림은 기존 종/알림함과 수신 설정을 사용하고 현재 볼 수 없는 대상은 링크·작성자 없는 일반 안내로 바뀐다. 실제 화면·반응형·키보드·저장/권한 흐름은 실행하지 않았다.

### 커뮤니티 글 증분 · 2026-10-08 (코드 작성, DB 미적용·실행 미검증)

`/community`에서 네 주제·제목/본문·연결 작품을 조합하고 최초 게시 최신순으로 20개씩 탐색한다. 연결 작품은 글 상세 작품 카드의 `이 작품의 다른 글`로 선택하고 조건 초기화로 해제한다. 스포일러 글은 제목·발췌·연결 작품 대신 일반 안내를 표시하며 숨긴 내용은 검색 대상에서도 제외한다. `/posts/[id]`의 명시적 펼치기는 현재 공개 권한과 게시 version을 다시 확인한다. 메타데이터는 사용자 내용을 포함하지 않는 일반 안내다.

`글 쓰기` → 초안 생성 POST → `/me/posts/[id]/edit`에서 작품 검색/최대 5개 선택, 주제·제목·본문·스포일러 입력 → 수동 초안 저장 → 저장본 미리보기 → 확인 후 게시 순서다. 자동 저장은 없다. 저장하지 않은 입력에는 안내와 브라우저 종료 경고를 제공하지만 앱 내부 링크 이동을 강제로 막지 않는다. 입력 중 변경이 있으면 게시 폼을 감추고 저장부터 안내한다. 저장 충돌은 최신 편집 화면에서 다시 확인해야 한다. 게시본 업데이트·공개 취소·삭제는 별도 동의이며 삭제 시 본문/초안/작품 연결을 제거한다.

공개 타인 글에서 신고와 기존 작성자 차단을 제공한다. `/me/post-reports`는 본인 접수/처리 결과, 운영 메뉴의 `/admin/post-reports`와 `/admin/posts/[id]`는 신고/감사·현재 게시본 확인·숨김/복구/기각이다. 비공개 수정 초안은 운영자에게 제공하지 않는다. 첫 공개 글은 팔로잉 피드에 연결하며 수정/재게시로 순서를 올리지 않는다. 글 좋아요·댓글·인기순·알림은 후속이다. 실제 화면·모바일·키보드·저장/권한 흐름은 실행하지 않았다.

**P4 공개 티어표 좋아요 · 2026-10-05 (작성·실행 미검증):** 최신 공개 목록에 실제 좋아요 수를 표시한다. 공개 상세는 좋아요/취소 버튼·현재 수·본인 상태 재조회를 제공하고 회원 여부/본인 콘텐츠 제한을 안내한다. 요청 중 버튼을 비활성화하고 서버 응답 뒤에만 수/aria-pressed를 갱신한다. 실패 시 확인된 값을 유지하되 게시 변경/권한 철회·모호한 응답에서는 상태를 다시 확인해야 한다. 스포일러는 좋아요 수를 보더라도 제목/본문/배치를 펼치기 전 공개하지 않는다. 링크 공개에는 좋아요 버튼/수 없이 비활성 안내만 표시한다. 차단/비활성 반응자에 따라 수는 현재 조회자에게 유효한 반응만 보여준다. 인기/태그 필터·댓글/팔로우는 후속이며 실제 브라우저·접근성 흐름은 확인하지 않았다.

## 4. 주요 화면 상세

### P1 실제 경로 구성 · 2026-10-02

인증/온보딩/프로필/계정/공개 범위·알림/공개 프로필 페이지와 Server Actions를 작성했다. `/auth/account-status`는 정지·삭제 중 계정 안내이며 `/auth/callback`만 Route Handler다. `/settings/notifications`는 `/settings/privacy`와 같은 설정 폼을 제공한다. 연결이 없으면 입력 가능한 가짜 폼 대신 연결 준비 안내를 표시한다. 로그인 전 회원 경로는 안전하게 검증한 returnTo를 보존한다. 실제 인증·저장·모바일·접근성 흐름은 이번 작업에서 미검증이다.

법적 안내 경로는 개발 미리 보기 버전임을 표시하고 원격 신규 가입은 앱에서 기본 비활성화한다. 아바타는 공개 파일임을 업로드 전에 표시한다. 탈퇴·데이터 내보내기는 P7 운영 작업을 구현하기 전까지 비활성 안내만 제공한다.

### P2 작성 경로 · 2026-10-02

`/explore`와 `/works/[slug]`, `/submissions/new`·`/submissions`, 카탈로그 관리용 `/admin`·`/admin/works`·`/admin/works/new`·`/admin/works/[id]/edit`·`/admin/works/merge`·`/admin/submissions`·`/admin/assets`·`/admin/audit`를 작성했다. 관리 경로는 verified/active/admin 계정만 사용하며 미설정 상태에는 연결 준비 안내를 제공한다. 일반 회원은 본인 제보와 처리 결과만 본다.

검색은 제목·별칭·작가명에 포함된 문자열을 대상으로 하며 초성·형태소·오타 유사 검색은 제공한다고 표시하지 않는다. 필터는 반복 URL 파라미터로 보존하고 같은 공식 링크에 플랫폼/요일을 함께 적용한다. 350ms 자동완성과 키보드로 접근 가능한 작품 링크를 작성했다. P3의 평점순/평가/리뷰/개인 서재 코드를 연결했으며 가짜 수치나 동작을 표시하지 않는다. 실제 DB와 화면 검수는 대기다.

표시 허가가 유효한 이미지 요청에 실패하면 텍스트 표지로 돌아간다. 병합은 결과/버전/표지 철회/남길 상태를 먼저 보여주며 확인과 사유를 요구한다. 제보 결과는 내 제보 화면과 본인 상세에서 확인하고, 2026-10-08 알림 증분부터 이후 처리분을 앱 안 알림에 연결한다. 이 화면들의 실제 브라우저·모바일·키보드·접근성 검수는 미실행이다.

### 홈

비회원: 서비스 한 문장 소개, 작품 검색, 최근 공개 티어, 최근 리뷰, 회원가입 유도. 회원: 최근 기록한 작품, 바로 이어서 편집할 티어, 팔로우 소식, 근거가 있는 추천. 빈 DB에서 가짜 인기 작품을 만들지 않고 첫 작품 제보와 사용법을 안내한다.

### 작품 탐색

검색창과 결과 수, 활성 필터 칩, 필터 초기화, 정렬, 작품 그리드를 제공한다. URL searchParams에 `q`, `platform`, `genre`, `status`, `day`, `sort`를 저장하여 뒤로 가기와 링크 공유를 지원한다. 다중 값은 반복 파라미터로 전달하고 서버에서 허용값을 검증한다.

한/두 글자 검색은 지원하되 결과 수와 요청 빈도를 제한한다. 초성 검색과 전문 형태소 분석을 제공한다고 표시하지 않는다. 오타 유사 검색과 별칭 검색의 범위를 명시한다.

### 작품 상세

상단: 자체 표지 또는 허가된 표지, 제목과 별칭, 작가/원작/그림 역할, 장르, 연재 상태, 플랫폼별 공식 링크. 중단: 내 서재 상태, 별점, 기본 티어, 평가 공개 범위. 하단: 사이트 전체 평점, 티어 분포, 독서 상태 조건별 평점, 리뷰, 이 작품을 좋아한 독자가 평가한 다른 작품.

외부 플랫폼의 평점과 이 서비스에서 모은 평점을 혼동하지 않도록 `ToonShelf 회원 평가`라고 표시한다. 플랫폼별 가격, 무료 회차 수, 실시간 연재 일정은 검증된 입력이 없는 한 표시하지 않는다.

`리뷰 쓰기`는 비회원에게 로그인 후 작품 페이지로 복귀하게 한다. 표본이 없으면 별점 0.0 대신 `아직 평가가 없어요`를 표시한다. 성인/숨김 작품은 상세 URL을 직접 열어도 일반 방문자에게 데이터가 나오지 않는다.

### 내 서재

보는 중/완독/중도하차/나중에 탭, 제목 검색, 태그, 장르, 플랫폼, 별점, 기본 티어 필터, 카드/목록 보기. 한 작품 편집 패널에서 상태, 회차, 날짜, 메모, 개인 태그, 공개 범위를 편집한다.

`서재 공개`와 `평가 공개`를 각각 설명한다. 메모와 회차는 항상 비공개임을 표시한다. 다중 선택으로 상태 변경, 태그 추가, 공개 범위 변경, 삭제를 지원한다. 대량 요청은 최대 100개 단위로 제한하고 부분 성공을 숨기지 않는다.

### 리뷰와 글 작성

제목이 필요한 커뮤니티 글과 작품에 연결된 리뷰를 구분한다. 리뷰에는 본문, 스포일러 전체 표시, 읽은 기준 회차를 입력한다. 현재 리뷰는 수동 저장 확인 후 저장된 초안을 별도 게시한다. 자동 초안 저장은 아직 구현하지 않았다. 글에는 카테고리와 관련 작품 최대 5개를 입력하며 P5에서 초안 저장과 게시를 분리해 연결한다.

게시 전 `이 내용은 공개됩니다`와 스포일러 선택을 확인한다. 오류가 발생해도 입력을 지우지 않는다. 삭제 시 댓글이 함께 접근 불가해짐을 안내한다.

### 티어 편집기

상단: 제목, 설명, 공개 상태, 마지막 저장 시각, 실행 취소/다시 실행, 미리보기, 게시. 데스크톱 왼쪽 패널: 작품 검색/내 서재와 추가 가능한 작품. 가운데: 티어 행. 하단: 미배치함.

모바일은 작품 추가를 바텀시트로 열고 `S로 이동`, `위로`, `아래로`, `미배치로` 메뉴를 제공한다. 드래그만으로 기능을 수행하게 만들지 않는다. 긴 제목도 잘리지 않은 접근성 이름을 제공한다.

저장 상태는 `변경 사항 없음`, `저장 중`, `저장 완료 23:10`, `오프라인: 이 기기에 임시 보관`, `저장 실패: 다시 시도`, `다른 화면에서 변경됨`을 구분한다. 오프라인 임시 보관을 서버 저장 완료라고 표시하지 않는다.

충돌창은 서버 최신 버전과 현재 편집본의 시각을 보여주고 `서버 버전 불러오기` 또는 `내 편집본을 새 티어표로 저장`을 제공한다. 다른 탭 변경을 자동으로 덮어쓰지 않는다.

기본 티어 가져오기는 개인 평가를 읽어 초안에 넣는다. 반대 방향은 명시적 반영 버튼만 사용한다. 한 표에 같은 작품을 두 번 놓을 수 없다.

**P4 게시·공유 증분 · 2026-10-04 (작성·실행 미검증):** 저장 대기/실패 중에는 편집 화면의 게시 이동을 막고, 저장 완료 후 `/tiers/[id]/publish`에서 저장된 초안의 제목·설명·행·배치만 미리 본다. 전체 공개/링크 공개, 스포일러 표시와 명시적 게시 확인을 선택한다. 다른 탭 저장·작품 공개 정보·게시 설정이 바뀌면 새 미리보기를 요구한다. 게시 후 초안은 계속 비공개로 편집한다.

OG 이미지·PNG·기본 평가 연결·인기/테마/소셜 반응·대표 티어는 후속이고 이번 사용자 흐름/화면 검수는 실행하지 않았다.

### 티어 게시본과 공유

작성자, 게시 시각, 버전, 설명, 행과 작품, 좋아요/댓글, 프로필, 내 표로 복제를 제공한다. 링크 공개 표는 탐색/피드/프로필에서 빠지고, 이번 버전에서는 좋아요와 댓글도 비활성화한다. URL을 가진 사람이 읽고 복제하는 것만 허용한다.

공개 URL에는 현재 게시본이 나온다. 초안을 변경하는 동안 기존 게시본은 유지된다. `게시본 업데이트` 후 내용이 바뀌며, 삭제/비공개 전환 시 익명 접근이 차단된다.

PNG 저장은 실제 전체 표를 여러 페이지로 내보내며, OG 미리보기는 고정 비율의 축약 카드다. 둘을 같은 이미지로 취급하지 않는다. 허가 범위가 화면 표시만 허용하면 PNG/OG에서는 텍스트 카드로 대체한다.

### 공개 티어 댓글·답글 · 2026-10-05 (작성·실행 미검증)

공개 상세에 댓글 첫 20개와 작성 폼, 전체 댓글 페이지 진입을 작성했다. 댓글은 최신순, 답글은 작성순이며 각 20개 페이지와 이전/다음은 원 댓글 ID를 유지한다. 비회원은 공개 목록과 명시적 스포일러 펼치기를 사용할 수 있고 작성에는 로그인/이메일 확인/활성·현재 동의가 필요하다. 링크 공개 표는 댓글을 표시하거나 작성하지 않는다. 읽은 적 없는 수를 채우지 않고 답글 수는 현재 조회 가능한 실제 자료만 집계한다.

티어표·원 댓글·개별 댓글의 스포일러를 함께 검사해 최초 원문을 제외한다. 펼치기·내 수정 원문은 별도 요청이며 현재 게시/댓글 버전을 재확인한다. 본인 삭제는 본문·작성자 표시를 지운 안내로 남겨 기존 답글을 유지하며 새 답글은 거절한다. 차단/운영 숨김/작성자 상태로 원 댓글이 가려지면 답글 스레드도 가려진다. 입력/서버 오류를 표시하고 응답 유실 시 입력을 유지하며 같은 요청으로 재시도한다. 수정·삭제·신고는 서버 응답 이후 새 자료를 불러온다.

내 댓글 신고 화면은 본인의 접수/처리 결과만, 운영 큐는 대기 신고 20개 페이지와 별도 검토 화면을 제공한다. 운영 검토에서도 원문을 명시적으로 펼치고 현재 public 표에만 hide/restore를 허용한다. 원 댓글 숨김은 답글을 함께 숨기고 복구는 현재 차단/계정/공개 조건을 다시 적용한다. 삭제된 본문은 복구하지 않는다. 비공개·링크 공개·삭제한 표 원문은 검토에도 제공하지 않으며 남은 대기 신고 기각만 가능하다. 브라우저/사용자 흐름/접근성 검수는 실행하지 않았다.

비교: 로그인 사용자 자신이 열람 가능한 평가와 상대의 공개 평가만 사용한다. 공통 작품 수, 점수, 신뢰도 안내, 둘 다 S인 작품, 차이가 큰 작품, 장르 공통점을 표시한다. 공통 비교 가능 작품이 5개 미만이면 숫자 점수를 숨긴다. 이 비교 화면의 결과는 다른 사람에게 공개하는 공유 기능을 만들지 않는다.

### 커뮤니티와 알림

목록은 카테고리, 최신/인기, 관련 작품 필터를 제공한다. 댓글 답글은 한 단계만 허용한다. 좋아요 버튼에 중복 요청 중 표시와 실패 시 원복을 구현한다.

알림에는 본문 원문을 저장하지 않는다. 알림 열람 시 대상이 삭제/비공개/차단되었는지 다시 확인하고 `더 이상 볼 수 없는 콘텐츠`로 표시한다. 알림 설정에서 종류별 수신을 끌 수 있다.

**알림 증분 · 2026-10-08 (코드·DB 반영, 실행 미검증):** 상단 종 버튼/계정 메뉴 → `/me/notifications`에서 전체·읽지 않음 필터, 20개 커서 페이지, 개별 읽음·모두 읽음·새로고침·설정 진입을 제공한다. 종에는 실제 읽지 않은 개수만 표시하고 실패/로딩을 0으로 꾸미지 않는다. 새 팔로워·티어 좋아요·댓글·답글·작품 제보 처리 결과를 받는다. 읽음은 서버 확인 후 갱신하며 응답 유실은 재조회 안내다. 모두 읽음은 화면을 불러온 시각까지의 생성분에 적용하므로 이후 생성분은 남긴다. 실시간 구독 없이 새 요청/새로고침에서 갱신하며 이미 받은 화면을 원격으로 회수하지 않는다.

알림의 댓글·답글은 `/tiers/[id]/comments/[commentId]`에서 현재 공개 접근을 다시 확인하고 기존 스포일러 확인 화면을 재사용한다. 제보는 `/submissions/[id]`의 본인 상세로 연결하여 최근 50개 목록 밖의 제보도 확인한다. 제목·본문·제보 원문/처리 내용은 알림 DTO에 없으며 대상 철회·삭제·차단·비활성·반응/팔로우 취소 시 작성자/대상 ID/원래 종류와 링크도 일반 안내로 대체한다. `/settings/notifications`의 종류별 선택은 이후 생성분부터 적용하고 기존 알림을 지우지 않는다. 이메일/브라우저 푸시와 서비스 공지 일괄 발송 UI는 이번 범위가 아니다. 실제 화면/사용자 흐름은 미검수다.

### 운영자 화면

신고 상세에 신고 대상, 사유, 접수/처리 시각, 권한 범위 내 원문, 조치 이력을 보여준다. 숨김/복구에는 사유가 필수다. 단순 신고 누적만으로 자동 삭제하지 않는다. 작품 등록에서 실제 API 연동이 없는 플랫폼의 연동 성공 표시를 만들지 않는다.

## 5. 대표 사용자 흐름

**첫 가입:** 회원가입 → 메일 확인 → 사용자 확인 동작 → 인증 성공 → 온보딩 → 좋아하는 장르 선택/건너뛰기 → 작품 검색 → 서재 저장. 이메일/소셜 인증과 앱 동의 상태를 각각 검증한다.

**평가:** 작품 상세 → 읽기 상태 선택 → 별점 또는 기본 티어 → 공개 범위 확인 → 서버 저장 → 같은 작품을 서재에서 열어 값 확인. 상태/평가를 함께 저장할 때 중간 불일치가 없어야 한다.

**티어 공유:** 표 생성 → 작품 추가 → 배치 → 초안 저장 확인 → 게시 미리보기 → 공개 범위 선택 → 게시 → URL 복사 → 시크릿 창에서 게시본 확인.

**다른 독자 발견:** 공개 티어 열람 → 작성자 프로필 → 내 취향과 비교 → 팔로우 → 팔로잉 피드에서 이후 공개 게시 확인.

**팔로잉 피드 증분 · 2026-10-07 (코드·DB 반영, 실행 미검증):** 데스크톱 주 메뉴/내 서재/계정 메뉴 → `/me/feed` → 공개 리뷰·티어 카드 → 현재 상세 또는 작성자 프로필이다. 모바일은 하단 내 서재/내 프로필에서 같은 경로로 진입한다. 첫 공개 이벤트의 생성 시각·UUID 내림차순 20개이며 수정/재게시로 순서를 올리지 않는다. 현재 공개된 기존 게시물도 초기 목록에 포함한다. 팔로우 없음·공개 게시물 없음·이전 목록 끝을 구분하고 독자 탐색, 이전 게시물 더 보기, 최신 게시물로 이동을 제공한다. 스포일러 원문/티어 제목은 목록에 없고 기존 상세 게이트에서 확인한다. 잘못된 커서/다른 계정의 커서는 최신 목록 안내, DB 실패는 공통 오류/재시도 화면이며 실패를 빈 목록으로 표시하지 않는다. 로딩·현재 권한/차단/철회·화면 동작은 코드만 작성했고 실제 흐름은 미검증이다.

**권리 철회:** 관리자 자산 검색 → 허가 철회 → 화면/PNG/OG 신규 요청에서 텍스트 커버로 대체 → 캐시 만료 확인 → 운영 기록 저장.

**탈퇴:** 영향 범위 확인 → 최근 재인증 → 탈퇴 확정 → 즉시 로그인/공개 노출 제한 → 삭제 작업 상태 확인. 서버 처리 중 오류가 나도 계정을 다시 공개하지 않는다.

## 6. 공통 상태와 접근성

모든 데이터 화면에서 loading, empty, success, error, forbidden 또는 not-found를 설계한다. 타인의 비공개 데이터는 존재 여부가 드러나지 않도록 동일한 not-found 응답을 우선한다.

폼 오류는 입력 옆과 폼 요약에서 확인 가능해야 하며 첫 오류로 포커스를 이동한다. 모달은 포커스를 가두고 닫힌 후 원래 버튼으로 돌린다. 저장/배치 결과는 aria-live로 알린다. 색상만으로 티어, 오류, 공개 상태를 구분하지 않는다.

터치 대상은 제품 기준 최소 44px를 목표로 한다. 360px, 768px, 1280px 뷰포트를 검수하고 본문 가로 스크롤을 허용하지 않는다. 표 편집 캔버스의 의도된 스크롤은 별도 안내한다. reduced-motion을 존중한다.

## 7. 메타데이터와 검색 노출

공개 작품, 공개 글, 공개 리뷰, 공개 티어, 공개 프로필만 정식 canonical을 가진다. sitemap에는 현재 접근 가능한 공개 항목만 포함한다. 비공개 전환/삭제 시 제거한다.

스포일러 리뷰는 OG 설명, 목록 발췌, 구조화 데이터, 초기 SSR/클라이언트 payload에 본문을 넣지 않는다. 본문 펼치기 후 별도 요청으로 불러온다. 스포일러 표시 자체는 접근 권한 보호가 아니라 제품상 노출 제어임을 구분한다.

링크 전용 공유는 `noindex, nofollow`, `Referrer-Policy: no-referrer`, 분석 로그 토큰 마스킹을 적용한다. 링크 전용 OG는 작품명 없이 일반 서비스 카드만 제공한다. noindex는 보안 수단이 아니며 토큰 검증은 별도로 필요하다.
